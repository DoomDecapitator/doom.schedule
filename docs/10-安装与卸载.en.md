# Installation and uninstallation

中文: `docs/10-安装与卸载.md`

## Check first, before installing

| Item | Requirement |
|---|---|
| Minecraft | Java Edition, 1.21.5 – 26.3 (shipped as two variants; see the mapping table in [../README.md](../README.md)). Verified: 32/32 passing on each of 1.21.5 / 1.21.10 / 26.3 |
| Experimental gameplay | No experimental features need to be enabled |
| Prerequisite datapacks | None. Does not require Bookshelf, does not require gu, does not require any library |
| Server / single-player | Either |

## 1. Single-player world

1. Download [`../dist/doom.schedule-v2.3.1.zip`](../dist/doom.schedule-v2.3.1.zip) (1.21.9–26.3). For 1.21.5–1.21.8, use [`../dist/doom.schedule-v2.3.1-mc1.21.5-1.21.8.zip`](../dist/doom.schedule-v2.3.1-mc1.21.5-1.21.8.zip) instead.
2. Unzip it. You get a folder `doom.schedule/` containing `data/`, `mcdoc/`, and `pack.mcmeta`.
3. Copy the whole folder into:

   ```
   %APPDATA%\.minecraft\saves\<your save>\datapacks\
   ```

   The final path looks like this. Note that `pack.mcmeta` must sit at exactly this level:

   ```
   ...\saves\<your save>\datapacks\doom.schedule\pack.mcmeta
   ...\saves\<your save>\datapacks\doom.schedule\data\doom.schedule\function\tick.mcfunction
   ```

   Common mistakes: nesting the `doom.schedule` folder one level too deep (giving `datapacks\doom.schedule\doom.schedule\pack.mcmeta`),
   or dropping `data/` in by itself. Neither will install.

4. Enter the world and type `/reload` in chat.
5. Type `/function doom.schedule:__help__`; the chat will list every available command. If you see that, it's installed.

## 2. Server

Same as single-player, except the destination directory becomes:

```
<server directory>\world\datapacks\doom.schedule\pack.mcmeta
```

Then there are two ways to make it take effect:

- Type `/reload` from the console / as an OP (no restart, the least hassle);
- Or restart the server.

> `/reload` does not clear the queue. The queue lives in `storage doom.schedule:data`, persists with the world, and survives a server restart.
> That's one of the reasons this pack exists.

## 3. Confirming it's really running

| Check | What to look at |
|---|---|
| Functions loaded successfully | `/function doom.schedule:__help__` produces output. If you get `Unknown or incomplete command`, the path is most likely nested one level wrong |
| The queue takes and returns tasks | `/function doom.schedule:schedule {run:'say 到了',time:5,unit:'s',id:'t1'}`; five seconds later "到了" appears in chat |
| Inspect the queue | `/data get storage doom.schedule:data queue` |
| Inspect the current game tick | `/function doom.schedule:get_time`, which does `return run time query gametime`; the return value is the current tick. Capture it with `/execute store result score ... run function ...` |
| Load errors | Search `logs/latest.log` on the server for `doom.schedule`, especially `Failed to load function` |

## 4. Uninstalling

1. Delete `datapacks/doom.schedule/`.
2. `/reload` (or restart the server).

This pack changes nothing in vanilla (it doesn't touch `doMobSpawning`, doesn't change spawn rules, adds no side effects beyond a scoreboard objective),
so deleting it restores everything. The only leftover is the few queue entries in `storage doom.schedule:data`;
if that bothers you, run this before deleting:

```
/function doom.schedule:clear
```

It empties all four queues: `processing` / `queue` / `offline` / `paused`.

## 5. Coexisting with other scheduler packs

`doom.schedule` uses only its own namespace `doom.schedule`, and only one scoreboard objective, `doom.schedule` (all its entries are fake players starting with `#`, so no real player names are taken).
It can be installed alongside other scheduler packs (`bs.schedule`, D-Better-Schedule, etc.) without interfering with them. Just don't schedule the same task with two schedulers.
