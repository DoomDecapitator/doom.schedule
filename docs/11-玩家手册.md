# 玩家手册 · 全部 API

> 所有命令都在 `doom.schedule` 命名空间下。带 `[宏]` 的必须用 `{...}` 传参。
> 想让别的数据包也能调用，用**函数标签**：`#doom.schedule:schedule`（= `doom.schedule:schedule`）、
> `#doom.schedule:cancel`、`#doom.schedule:clear` —— 这样将来包内部改了函数名，你的调用也不用改。

## 一、时间单位

| 写法 | 单位 | 换算 |
|---|---|---|
| `t` / `tick` | 游戏刻 | 1 |
| `s` / `second` | 秒 | 20 |
| `m` / `minute` | 分钟 | 1200 |
| `h` / `hour` | 小时 | 72000 |
| `d` / `day` | Minecraft 天 | 1728000 |

写别的字符串会**报错并 `return fail`**（聊天栏会给一条红字 `[doom.schedule] invalid unit: xxx`），不会静默丢弃。

## 二、调度一个任务

```
function doom.schedule:schedule {run:'say hello',time:20,unit:'t',id:'my_task'}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `run` | 字符串 | ✅ | 到点执行的命令（**不带前导斜杠**） |
| `time` | 整数 | ✅ | 延迟数值，配合 `unit` |
| `unit` | `'t'`/`'s'`/`'m'`/`'h'`/`'d'` | ✅ | 时间单位（引号单双皆可） |
| `id` | 字符串 | ✅ | 任务 ID，取消/暂停/恢复都按它找 |

**返回值**：成功 `return 1`；单位非法 `return fail`。

**入队时会被冻结的东西**（执行时原样还原）：

| 字段 | 从哪来 | 用途 |
|---|---|---|
| `by` | 执行者 UUID（4 个 int → 32 位十六进制字符串） | 执行时 `execute as <那个实体>`，O(1) 定位 |
| `is_player` | 执行者是玩家则 `1b` | 决定掉线时是"进离线队列"还是"静默丢弃" |
| `dim` | `@s` 的 `Dimension`；没有实体就按 `if dimension` 判 3 个原生维度 | 到点在哪个维度执行 |
| `posX/posY/posZ`、`rotX/rotY` | 入队时 `@s` 的位置与朝向 | 到点 `positioned` + `rotated` 还原 |
| `exec_time` | `gametime + time × scale` | 到点判据（绝对游戏刻） |

> 在**命令方块 / 控制台**里调度时没有执行实体，位置就取命令源自己的坐标（1.21 的 `/execute` 语义），
> 维度按 `if dimension` 判原生三维度；自定义维度要自己注册，见 [12-配置与自定义维度](12-配置与自定义维度.md)。

## 三、带重试

```
function doom.schedule:schedule_with_retry {run:'say hi',time:20,unit:'t',id:'rt',retry:3,retry_delay:5}
```

| 参数 | 说明 |
|---|---|
| `retry` | 执行**失败后**的额外重试次数。`retry:3` = 首次 + 最多再试 3 次，共 4 次尝试 |
| `retry_delay` | 每次重试间隔（tick）。≤ 0 会被自动修正为 1 |

- 重试**只在命令返回失败时**发生（`execute store success` 拿到 0）。
- "命令失败"包括：目标实体不在了、`execute as` 找不到人、命令本身语法/条件不成立。
- 重试次数耗尽后任务**被丢弃**（不会无限重试）。

## 四、取消

```
function doom.schedule:cancel_one {id:'my_task'}      # 推荐：删第一条匹配
function doom.schedule:cancel {id:'my_task'}          # 旧别名，等价于 cancel_one
function doom.schedule:cancel_all {id:'group_a'}      # 删掉所有匹配
function doom.schedule:clear                          # 清空全部队列
```

| 命令 | 扫描范围 | 删几条 | 返回值 |
|---|---|---|---|
| `cancel_one` | `queue[]` → `offline[]` → `paused[]` | **只删第一条** | `#removed`（1 = 删到了，0 = 没找到） |
| `cancel_all` | `processing[]` + `queue[]` + `offline[]` + `paused[]` | 全部匹配 | `#removed`（各类命中数之和） |
| `clear` | 四条队列全部 | 清空 | 无 |

- `cancel_one` **不碰本 tick 的 `processing[]`** —— 也就是在任务自己的 `run` 里取消自己是无效的。
- `cancel_all` 和 `clear` **会**处理 `processing[]`。
- 扫描是 FIFO 逐条做的，不会打乱队列顺序。

## 五、暂停与恢复

```
function doom.schedule:pause {id:'my_task'}     # queue[] → paused[]（第一条匹配）
function doom.schedule:resume {id:'my_task'}    # paused[] → queue[]（第一条匹配）
```

- `paused[]` 是一条**独立队列**，`restore`（离线恢复）**不会**碰它 —— 暂停就是真暂停，玩家上下线都不影响。
- 两者都返回 `#removed`（1 = 动到了，0 = 没找到）。
- `pause` 只扫 `queue[]`，不动本 tick 的 `processing[]`。
- 恢复后的任务**重新排到队尾**，`exec_time` 保持不变 —— 也就是说，如果暂停期间早就过点了，`resume` 后**下一拍就会立刻执行**。

## 六、快速调度

```
function doom.schedule:api/schedule_dynamic {run:'say hi',time:20,unit:'t',prefix:'demo'}
```

- 用 `prefix` **直接当 `id`**，不做自增、不做去重。
- 需要唯一 ID 就别用它，直接用 `schedule`。

## 七、其他

| 命令 | 作用 |
|---|---|
| `function doom.schedule:get_time` | `return run time query gametime` —— **返回值是当前游戏刻**，不写 storage |
| `function doom.schedule:__help__` | 往聊天栏打一段用法提示 |
| `function doom.schedule:__load__` | 由 `#minecraft:load` 自动调用；手动跑会重建常量表并打一行 `[doom.schedule] loaded` |
| `function doom.schedule:__unload__` | 清理用 |

## 八、到点之后会发生什么（`looper_exec` 分流表）

任务到期后进 `processing[]`，`internal/execute/run` 先测目标在不在线，再决定去向：

| `#target_online` | `#success` | 有 `retry` | `is_player` | 结果 |
|---|---|---|---|---|
| 0 | — | — | true | 移入 `offline[]`，等玩家回来 |
| 0 | — | — | false | 静默丢弃（实体没了，任务没有意义） |
| 1 | 1 | — | — | 完成，出队 |
| 1 | 0 | true | — | `retry` 减 1，`retry_delay` 后重入队 |
| 1 | 0 | false | — | 丢弃 |
| 无 `by` | 0 | true | — | 用命令源坐标重试 |
| 无 `by` | 0 | false | — | 丢弃 |

## 十、已知限制（诚实清单）

- `cancel_one` / `pause` **不作用于本 tick 的 `processing[]`** —— 在任务自己的 `run` 里取消或暂停自己是无效的。
  要那种语义请用 `cancel_all` / `clear`。
- `offline[]` **不接受手动写入**。它只由 `looper_exec` 的离线分流维护，手写进去的条目缺少
  `by` / `dim` / `pos*` 等字段，`restore` 会拿它没办法。
- 暂停后恢复的任务**不会重新计时**（`exec_time` 冻结），过点了就立刻执行。这是刻意的：暂停的是"什么时候执行"，
  不是"再等多久"。
- 任务是**逐 tick 全量遍历**的（`looper_scan` 扫过整个到期集合）。任务量上千时会有可观的 MSPT 开销 ——
  它面向的是"几十到几百个定时任务"的服务端场景，不是给自己写一个 tick 级循环任务用的。
- 本包**不做去重**：同一个 `id` 排两次就是两条任务，`cancel_one` 只删得掉其中一条。
