# 配置与自定义维度

这个包没有配置文件。所谓“配置”，要么是调用时传的参数，要么是 storage 里的数据，要么是一个函数标签。

## 一、storage 布局（全部）

| Storage | 谁写 | 里面是什么 |
|---|---|---|
| `doom.schedule:const` | `__load__` | `units[]`（时间单位表）· `hex_chars[]`（256 项十六进制查表）。只读，别手改 |
| `doom.schedule:data.queue[]` | `schedule` 入队 / `looper` 取出 | 待调度任务（FIFO） |
| `doom.schedule:data.offline[]` | `looper_exec` 分流 | 目标离线被冻结的任务。只由包自己维护，别手写 |
| `doom.schedule:data.paused[]` | `pause` / `resume` | 用户暂停的任务 |
| `doom.schedule:ctx.processing[]` | `looper` | 本 tick 搬出来要判定的任务堆。每 tick 清空重建，别依赖它 |
| `doom.schedule:ctx.task` / `scan` / `current` / `_` / `temp_retry` | 各个函数 | 运行时临时数据，同一 tick 内用完即删 |

一条任务长这样（`queue[]` 里的一项）：

```snbt
{
  run: "say hello",           // 到点执行的命令
  time: 100,                  // 延迟数值（原始输入）
  unit: "s",                  // 时间单位（原始输入）
  id: "my_task",              // 任务 ID
  exec_time: 128400,          // 绝对游戏刻 = 入队时 gametime + time*scale
  by: "069a79f4-...",         // 目标实体 UUID（无实体任务没有这个字段）
  dim: "minecraft:overworld", // 维度
  posX: 0.5, posY: 70.0, posZ: 0.5, rotX: 0.0, rotY: 0.0,
  is_player: 1b,              // 是玩家则为 1b
  retry: 3,                   // 可选：剩余重试次数
  retry_delay: 5              // 可选：重试间隔 tick
}
```

对应的结构定义在 [`../doom.schedule/mcdoc/doom.schedule.mcdoc`](../doom.schedule/mcdoc/doom.schedule.mcdoc)，
它是给编辑器补全用的（见下面第四节）。

## 二、计分板

只有一个目标：

```
doom.schedule  (dummy)
```

里面全是 `#` 开头的假玩家（不占真人玩家名，也不会显示在侧边栏）：

| 假玩家 | 用途 |
|---|---|
| `#256` | 常量 256，`uuid_hex` 换算用 |
| `#suid` | 内部计数 |
| `#scale` / `#delay` / `#time` | `schedule` 里算 `exec_time` |
| `#target_online` / `#success` | `looper_exec` 的判定结果 |
| `#retry` / `#now` | `retry` 里算下一次的 `exec_time` |
| `#exec_now` / `#time_now` | `looper_scan` 的到期判定 |
| `#removed` / `#removed_*` | `cancel*` / `pause` / `resume` 的返回值 |
| `#restore_count` / `#restore_online` | `restore` 的每 tick 上限与在线判定 |

要在聊天栏看某个值：`/scoreboard players get #removed doom.schedule`。

## 三、自定义维度注册

实体调度不需要注册：入队时会直接读 `@s` 的 `Dimension` 字段，任何维度（包括 Mod 加的维度）都能记住。

只有没有执行实体时才需要注册（命令方块、控制台、`/execute` 里没有 `as`）：
那时包只能靠 `execute if dimension` 去猜，而它内置只认 `minecraft:overworld` / `the_nether` / `the_end`。

三步：

1. 查维度 ID（站在那个维度里打）

```
/data get entity @s Dimension
```

2. 写一个检测函数，把结果写进 `doom.schedule:ctx._.dim`：

```mcfunction
# data/your_datapack/function/detect_void.mcfunction
execute if dimension mymod:void run data modify storage doom.schedule:ctx _.dim set value "mymod:void"
```

3. 注册进标签：编辑数据包里的

```
doom.schedule/data/doom.schedule/tags/function/known_dimensions.json
```

```json
{
  "values": [
    "your_datapack:detect_void"
  ]
}
```

这个标签默认是空的（`{"values": []}`），包在 `dim_scan` 里会按顺序把里面每个函数都跑一遍。

> 注意：这是改数据包本体的文件。如果你还想让 `dist/` 的 zip 保持一致，请自己重新压一个 zip
> （zip 内顶层目录必须是 `doom.schedule/`）。

## 四、编辑器补全（mcdoc）

包里带了 [`mcdoc/doom.schedule.mcdoc`](../doom.schedule/mcdoc/doom.schedule.mcdoc)，声明了
`doom.schedule:data`、`doom.schedule:const`、`doom.schedule:ctx` 三个 storage 的结构。

- Spyglass（VS Code 扩展）：装好即可，改 `.mcfunction` 时自动生效。
- Misodee.vscode-mcdoc：同样即插即用。

生效后，你打：

```mcfunction
data modify storage doom.schedule:data queue append value {
```

编辑器会列出 `run` / `time` / `unit` / `id` / `exec_time` / `by` / `dim` / `posX` … 每个字段并附上说明。

示例函数见 [`../doom.schedule/data/doom.schedule/function/mcdoc.mcfunction`](../doom.schedule/data/doom.schedule/function/mcdoc.mcfunction)，
它把三条队列 + 常量 + 运行时上下文的写法各写了一遍，可以直接 `function doom.schedule:mcdoc` 跑一遍看补全提示。

## 五、性能相关的旋钮

这个包没有提供“每 tick 处理上限”之类的开关，因为它本来就不是给海量任务设计的。真正影响开销的只有两处：

| 位置 | 行为 | 想省的话 |
|---|---|---|
| `looper` / `looper_scan` | 每 tick 把整条队列搬到 `processing[]`，逐条比 `exec_time`，没到期的再塞回 `queue[]` | 不要把“几秒后”的任务排几千条；能用 `/schedule` 的原生延迟就别排进来 |
| `restore` | 离线队列每 tick 最多恢复 10 条（`#restore_count` 一到 10 就停，下一 tick 继续） | 不用调，这是刻意压住峰值的设计 |

真机上的 MSPT 数字、压力测试脚本与逐轮报告都在开发仓库（不对外），玩家向仓库不带这些。
