# 安装与卸载

## 装之前先确认

| 项 | 要求 |
|---|---|
| Minecraft | Java 版，**1.21.5 – 26.3**（分两份变体下发，映射表见 [../README.md](../README.md)）。实测：1.21.5 / 1.21.10 / 26.3 三台各 32/32 通过 |
| 实验性玩法 | **不需要开任何实验性玩法** |
| 前置数据包 | **没有**。不吃 Bookshelf、不吃 gu、不吃任何库 |
| 服务端 / 单人 | 都行 |

## 一、单人存档

1. 下载 [`../dist/doom.schedule-v2.3.1.zip`](../dist/doom.schedule-v2.3.1.zip)（1.21.9–26.3）。1.21.5–1.21.8 改用 [`../dist/doom.schedule-v2.3.1-mc1.21.5-1.21.8.zip`](../dist/doom.schedule-v2.3.1-mc1.21.5-1.21.8.zip)。
2. 解压。得到一个文件夹 `doom.schedule/`，里面是 `data/` 与 `mcdoc/` 和 `pack.mcmeta`。
3. 把它**整个**复制到：

   ```
   %APPDATA%\.minecraft\saves\<你的存档>\datapacks\
   ```

   最终路径长这样 —— 注意 `pack.mcmeta` 必须**正好**在这一层：

   ```
   ...\saves\<你的存档>\datapacks\doom.schedule\pack.mcmeta
   ...\saves\<你的存档>\datapacks\doom.schedule\data\doom.schedule\function\tick.mcfunction
   ```

   常见错法：把 `doom.schedule` 这个文件夹**多套了一层**（变成 `datapacks\doom.schedule\doom.schedule\pack.mcmeta`），
   或者直接把 `data/` 丢进去。这两种都装不上。

4. 进世界，聊天栏打 `/reload`。
5. 打 `/function doom.schedule:__help__` —— 聊天栏会列出全部可用命令，看到就说明装上了。

## 二、服务器

和单人一样，只是目标目录换成：

```
<服务端目录>\world\datapacks\doom.schedule\pack.mcmeta
```

然后**两种生效方式**：

- 控制台 / OP 打 `/reload`（不重启，最省事）；
- 或者重启服务端。

> `/reload` 不会清空队列 —— 队列在 `storage doom.schedule:data`，随存档持久化，重启服务端也不会丢。
> 这正是这个包存在的理由之一。

## 三、确认它真的在跑

| 检查 | 看什么 |
|---|---|
| 函数加载成功 | `/function doom.schedule:__help__` 有输出。若报 `Unknown or incomplete command`，多半是路径套错层了 |
| 队列能进能出 | `/function doom.schedule:schedule {run:'say 到了',time:5,unit:'s',id:'t1'}`，5 秒后聊天栏出现"到了" |
| 看队列现状 | `/data get storage doom.schedule:data queue` |
| 看当前游戏刻 | `/function doom.schedule:get_time` —— 它 `return run time query gametime`，返回值就是当前刻；配 `/execute store result score ... run function ...` 取用 |
| 加载报错 | 服务端 `logs/latest.log` 里搜 `doom.schedule`，尤其 `Failed to load function` |

## 四、卸载

1. 删掉 `datapacks/doom.schedule/`。
2. `/reload`（服务器可重启）。

这个包**不改原版任何东西**（不碰 `doMobSpawning`、不改生成规则、不加计分板目标以外的副作用），
所以删掉即恢复。唯一残留是 `storage doom.schedule:data` 里那几条队列数据，
介意的话在删之前先打：

```
/function doom.schedule:clear
```

它会清空 `processing` / `queue` / `offline` / `paused` 四条队列。

## 五、和别的调度包共存

`doom.schedule` 只用自己的命名空间 `doom.schedule`，计分板只用 `doom.schedule` 这一个目标（都是 `#` 开头的假玩家，不占玩家名）。
和别的调度包（`bs.schedule`、D-Better-Schedule 等）**可以同时装**，它们互不干扰 —— 只是别对同一个任务用两家调度。
