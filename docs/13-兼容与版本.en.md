# Compatibility and versions

中文: `docs/13-兼容与版本.md`

## 1. Version matrix (1.21.5 → 26.3)

Starting with 1.21.9, MC tightened the datapack metadata rules: `pack.mcmeta` must declare
`min_format` / `max_format`, and they must match the `supported_formats` range value by value;
a mismatch or a missing field means the whole pack is rejected. And 1.21.5–1.21.8 doesn't recognize those two new fields.
A single mcmeta cannot satisfy both sides, so this pack is split into two variants (byte-identical command layers, differing only in `pack.mcmeta`).

### Which one to use (mapping table)

| MC version | data format | Which variant | `pack.mcmeta` | Verified |
|---|---|---|---|---|
| 1.21.5 | 71 | `...-mc1.21.5-1.21.8` | `pack_format 71` + `sf 71–81` + `min [71,0]` + `max 81` | ✅ 32/32 |
| 1.21.6 | 80 | `...-mc1.21.5-1.21.8` | Same as above | 🟡 Extrapolated from the same range |
| 1.21.7 / 1.21.8 | 81 | `...-mc1.21.5-1.21.8` | Same as above | 🟡 Extrapolated from the same range |
| 1.21.9 / 1.21.10 | 88.0 | `v2.3.1` ★ | New style only: `min [88,0]` + `max 121` | ✅ 32/32 (1.21.10) |
| 1.21.11 | 94.1 | `v2.3.1` ★ | Same as above | 🟡 Extrapolated from the same range |
| 26.1 / 26.1.1 / 26.1.2 | 101.1 | `v2.3.1` ★ | Same as above | 🟡 Extrapolated from the same range |
| 26.2 | 107.1 | `v2.3.1` ★ | Same as above | 🟡 Extrapolated from the same range |
| 26.3 | 121.0 | `v2.3.1` ★ | Same as above | ✅ 32/32 |

★ = the primary variant, the one installed by [`dist/doom.schedule-v2.3.1.zip`](../dist/doom.schedule-v2.3.1.zip).
The other one is [`dist/doom.schedule-v2.3.1-mc1.21.5-1.21.8.zip`](../dist/doom.schedule-v2.3.1-mc1.21.5-1.21.8.zip).

### The two `pack.mcmeta` files verbatim

`...-mc1.21.5-1.21.8` (1.21.5 – 1.21.8):

```json
{
  "pack": {
    "pack_format": 71,
    "supported_formats": { "min_inclusive": 71, "max_inclusive": 81 },
    "min_format": [71, 0],
    "max_format": 81,
    "description": "doom.schedule — Fusion scheduler"
  }
}
```

`v2.3.1` (1.21.9 – 26.3 ★ primary, new style only):

```json
{
  "pack": {
    "min_format": [88, 0],
    "max_format": 121,
    "description": "doom.schedule — Fusion scheduler"
  }
}
```

> The iron rule of consistency: `min_format` must equal `supported_formats.min_inclusive`,
> and `max_format` must equal `supported_formats.max_inclusive`. And when `min_format < 82`,
> `pack_format` and `supported_formats` are still required — missing either one gets you rejected.
> But when the declared range touches 82+, `supported_formats` becomes forbidden and the new style only must be used.

> The range is not a load gate: a dedicated server force-enables packs under `world/datapacks`,
> so an out-of-range `max_format` is not rejected. The real consequences are misstated metadata, a misleading
> "data pack selection" screen on the client, and code that may simply break on an out-of-range version.
> This pack has no `gamerule` use and no version-sensitive code, so going out of range won't crash,
> but both mcmeta files have still been tightened to exactly their respective tested coverage ranges (M6: declared ⊆ actual).

Only three machines have been verified on real hardware: 1.21.5 / 1.21.10 / 26.3.

## 2. Unrelated to experimental gameplay

This pack uses no experimental gameplay content (no custom enchantments, no experimental entities, no changes to world generation).
Therefore:

- When creating a single-player world, no experimental switches need to be ticked;
- Servers need no experimental launch parameters;
- Between MC patch versions you can swap the pack directly, without recreating the world.

## 3. Upgrading / downgrading

| Scenario | What to do |
|---|---|
| Upgrading from an older doom.schedule to v2.3.1 | Delete the old `datapacks/doom.schedule/`, put the new `doom.schedule/` in, `/reload`. Queue data is not lost (it lives in `storage`, and a function reload doesn't clear it) |
| Downgrading to an older version | Same as above. But note: pack bodies before v2.2 have a defect on the "entity-less task" path (see [CHANGELOG](../CHANGELOG.md)); downgrading means installing those two bugs again |
| Switching MC version (1.21.8 → 1.21.9) | Switch to the `v2.3.1` build (the two command layers are byte-identical). An old-style mcmeta will be rejected outright by 1.21.9 |
| Switching MC version (1.21.10 → 1.21.11 and later) | The primary variant already covers up to 26.3; no pack swap needed |
| Starting from scratch (wanting to empty the queue) | `/function doom.schedule:clear`, then delete the pack and reinstall |

`storage doom.schedule:data` is bound to the save; switching saves means switching to a different queue, with no cross-effects.

## 4. Comparison with other scheduler packs

| Comparison item | bs.schedule | D-Better-Schedule | **doom.schedule v2.3.1** |
|---|---|---|---|
| Function count | ~20 | ~60 | 35 |
| Scheduling method | Vanilla `/schedule` fire-once | `#tick` polling | `#tick` polling |
| UUID targeting | Scoreboard + predicate | `gu` library hex → `execute as` | 4 int → hex → `execute as $(by)` |
| Offline recovery | ❌ | ✅ `offline[]` | ✅ `offline[]` + restore (10/tick) |
| Failure retry | ❌ | ✅ | ✅ `schedule_with_retry` |
| Pause/resume | ❌ | ✅ | ✅ separate `paused[]` queue |
| Cancel | Partial | ✅ | ✅ `cancel_one` / `cancel_all` / `clear` |
| External dependencies | None | The `gu` library | None |
| Cross-dimension | Manual | Manual | Automatic for entities; registerable for entity-less scheduling |
| License | See its repository | See its repository | MIT |

They can be installed together: the three packs each use their own namespace and don't conflict.

## 5. Relationship with vanilla `/schedule`

No conflict; they coexist. doom.schedule doesn't touch vanilla `/schedule`, nor does it clean up other packs' native scheduled tasks.

Which one to use:

| Your need | Use which |
|---|---|
| Run a fixed function a few ticks later; no need to track anyone or cancel | Vanilla `/schedule` — it costs less |
| Tasks must know their target, survive a save/server restart, be cancellable/pausable, and retry on failure | doom.schedule |

## 6. Known incompatibilities / limitations

- 1.20.x and earlier are not supported: the format number is below the declared range, and the game judges it a mismatch outright.
- ~~1.21.9+ not supported~~ → supported since v2.3.1 (use the primary variant).
- There is only one `pack_format`: this pack doesn't do multi-version branching (unlike some packs that ship both a 1.20 and a 1.21 set of `data/`); the command layers of the two variants are byte-identical, only `pack.mcmeta` differs.
- The `mcdoc/` directory is not game content: `mcdoc/` sits alongside `pack.mcmeta` and `data/`, and the game ignores it;
  deleting it doesn't affect running, you just lose editor completion.
