二、和实验性玩法无关

这个包**不使用任何实验性玩法内容**（没有自定义附魔、没有实验性实体、没有改世界生成）。
所以：

- 单人建世界时**不用**勾任何实验性开关；
- 服务端**不用**加实验性启动参数；
- 各 MC 小版本之间可以直接换包，不用重开世界。

## 三、升级 / 降级

| 场景 | 怎么做 |
|---|---|
| 从旧版 doom.schedule 升到 v2.3.1 | 删掉旧的 `datapacks/doom.schedule/`，把新的 `doom.schedule/` 放进去，`/reload`。**队列数据不会丢**（它在 `storage` 里，函数重载不清理） |
| 降级回旧版 | 同上。但注意：v2.2 之前的包体在"无实体任务"路径上有缺陷（见 [CHANGELOG](../CHANGELOG.md)），降级等于把那两个 bug 装回来 |
| 换 MC 版本（1.21.8 → 1.21.9） | **换成 `v2.3.1` 那份**（命令层两份逐字节相同）。用旧式 mcmeta 会被 1.21.9 **直接拒收** |
| 换 MC 版本（1.21.10 → 1.21.11 及以后） | 主用变体已覆盖到 26.3，**无需换包** |
| 从零开始（想清空队列） | `/function doom.schedule:clear`，然后删包重装 |

`storage doom.schedule:data` 与存档绑定；换存档等于换一份队列，互不影响。

## 四、和别的调度包对比

| 对比项 | bs.schedule | D-Better-Schedule | **doom.schedule v2.3.1** |
|---|---|---|---|
| 函数数 | ~20 | ~60 | **35** |
| 调度方式 | 原版 `/schedule` fire-once | `#tick` 轮询 | **`#tick` 轮询** |
| UUID 定位 | 计分板 + predicate | `gu` 库 hex → `execute as` | **4 int → hex → `execute as $(by)`** |
| 离线恢复 | ❌ | ✅ `offline[]` | **✅ `offline[]` + restore（10/tick）** |
| 失败重试 | ❌ | ✅ | **✅ `schedule_with_retry`** |
| 暂停/恢复 | ❌ | ✅ | **✅ 独立 `paused[]` 队列** |
| 取消 | 部分 | ✅ | **✅ `cancel_one` / `cancel_all` / `clear`** |
| 外部依赖 | 无 | `gu` 库 | **无** |
| 跨维度 | 手动 | 手动 | **实体自动；无实体可注册** |
| 许可 | 见其仓库 | 见其仓库 | **MIT** |

可以同时装：三个包各用各的命名空间，互不冲突。

## 五、和原版 `/schedule` 的关系

**不冲突，可以共存。** doom.schedule 不去动原版的 `/schedule`，也不清理别人的原生调度任务。

该用哪个：

| 你的需求 | 用谁 |
|---|---|
| 几 tick 后跑一个固定函数，不需要追踪谁、不需要取消 | 原版 `/schedule` —— 它的开销更低 |
| 任务要认人、要跨存档重启、要能取消/暂停、要失败重试 | doom.schedule |

## 六、已知不兼容 / 限制

- **不支持 1.20.x 及更早**：格式号低于 declared 区间，游戏会直接判不符。
- ~~不支持 1.21.9+~~ → **v2.3.1 起已支持**（用主用变体）。
- **`pack_format` 只有一个**：这个包不做多版本分支（不像有些包同时带 1.20/1.21 两套 `data/`）；两份变体的**命令层逐字节相同**，只有 `pack.mcmeta` 不同。
- **`mcdoc/` 目录不是游戏内容**：`mcdoc/` 与 `pack.mcmeta`、`data/` 平级，游戏会忽略它；
  删掉不影响运行，只是编辑器没补全了。
