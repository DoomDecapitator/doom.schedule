## 2. Third-party boundaries

| Item | Status |
|---|---|
| Game assets | No Mojang assets are included. `data/` contains only mcfunction files and JSON tags — no textures, models, or sounds |
| Third-party datapacks | No third-party library is referenced or bundled. Does not require Bookshelf (`bs.*`), does not require `gu`, does not require any `lib_*` |
| Vanilla functions | Only vanilla commands are called (`data` / `execute` / `scoreboard` / `tellraw` / `return` / `time`); no vanilla functions or tags are overridden |
| Generator | None. This pack is hand-written mcfunction; the repository has no `src/`, and nothing requires running a script to produce (see [the "Where the source is" section of the README](../README.md)) |
| mcdoc definitions | Written in-house, in the publicly documented mcdoc format (the Spyglass / Misode editor plugins); none of their code is included |

## 3. Credits

- Mojang / Microsoft, for Minecraft Java Edition, and for the `execute ... summon`,
  `return run`, `data modify ... set from`, and `storage` command capabilities added in this version that make a "pure datapack scheduler" feasible.
- Spyglass / Misode, for the `mcdoc` editor completion scheme and its public format documentation.
- bs.schedule / D-Better-Schedule, the scheduler datapacks that went first in this ecosystem. This pack uses their trade-offs as a comparison table
  (see [13-兼容与版本](13-兼容与版本.md)); this pack's "offline queue + retry + pause" trio grew directly out of those trade-offs.

## 4. Feedback

If you get stuck installing, a task doesn't fire when due, or you find a pitfall this documentation doesn't cover, report it in the repository's
[Issues](https://github.com/DoomDecapitator/doom.schedule/issues). The form asks for four things —
pack version · Minecraft version · reproduction steps · logs. Missing any of them makes it much harder to investigate.

For security issues, follow the instructions in the Issues; don't paste server addresses or player UUIDs into a public issue.
